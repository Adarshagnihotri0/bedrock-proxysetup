# ADR-003: Canonical Domain Boundary

**Status**: Accepted  
**Date**: 2026-07-18  
**Depends On**: ADR-001 (Evidence), ADR-002 (Knowledge)  
**Implements**: Phase 3 Projection Infrastructure

---

## Context

The architecture has evolved from application-level design to infrastructure-grade knowledge platform. We need clear domain boundaries that remain stable across implementation changes.

---

## Decision

Each architectural layer owns exactly one responsibility:

| Layer | Owns |
|-------|------|
| Evidence | Reality (what happened) |
| Knowledge | Meaning (what it means) |
| Projection | Representation (how to view it) |
| Retrieval | Access (how to query it) |
| Reasoning | Inference (what follows) |
| Planning | Decisions (what to do) |
| Execution | Side Effects (what changes) |

**One sentence per layer:**

- Evidence owns reality.
- Knowledge owns meaning.
- Projection owns representation.
- Retrieval owns access.
- Reasoning owns inference.
- Planning owns decisions.
- Execution owns side effects.

---

## Consequences

### Layer Isolation

No layer may assume implementation details of another layer.

**Example**: Projection doesn't know if Knowledge used PostgreSQL or MongoDB.

**Example**: Retrieval doesn't know if Projection used Graphiti or Neo4j.

---

### Vertical Boundaries

Events flow downward. Data flows upward.

```
Events:    Reality → Evidence → Knowledge → Projection → Retrieval
Data:      Actions ← Execution ← Planning ← Reasoning ← Retrieval
```

---

### Replaceability

Any layer's implementation can be swapped without changing the layer above.

**Evidence**: PostgreSQL → EventStore  
**Knowledge**: PostgreSQL → FoundationDB  
**Projection**: Graphiti → Neo4j  
**Retrieval**: Graphiti API → Custom indexer

Domain boundary remains stable.

---

### Ontology Preservation

Each layer must preserve semantic meaning from above.

```
Knowledge → Projection → Retrieval → Knowledge-equivalent meaning
```

Backends may optimize storage but not change meaning.

## Enforcement

Any PR that violates domain boundaries must be rejected.

**Violation examples**:
- Evidence layer accessing Knowledge tables
- Projection exposing Graphiti types to Retrieval
- Retrieval bypassing Projection to access Knowledge directly

**Enforcement**: Architecture review in PR template.
